# CourseSniffer 实验 1A 演示方案与脚本

本次成片时长 2 分 46 秒。视频连续录制 Qt 窗口，讲解采用内嵌中文字幕。实际分段时间见 SRT 字幕文件。

## 一、录制准备

在项目根目录运行录制脚本。

```bash
bash scripts/record_demo_macos.sh
```

脚本检查 C++17、Qt6、libpcap 和 FFmpeg 等依赖，构建程序并运行四组 CTest 测试，取得系统管理员授权后启动自动演示。

构建与单元测试结果保存在日志中。录制范围仅包含 CourseSniffer 的 Qt 窗口。

## 二、物理网卡抓包与混杂模式

### 操作

1. 选择默认路由对应的物理网络接口，通过 libpcap 请求混杂模式。
2. 设置抓包过滤器，将捕获范围限定为本机与默认网关之间的 IPv4 ICMP 通信。
3. 开始抓包，向默认网关发送三次 ICMP Echo 请求。
4. 展示程序界面顶部的模式请求和 API 激活结果。本机录制记录显示 API 接受混杂模式请求，pcap_activate 返回 0，捕获三个请求和三个应答。
5. 查看请求报文的 Ethernet 字段，随后选中应答报文，查看 ICMP 字段。
6. 停止抓包并清空记录，切换至回环接口 lo0。

### 字幕讲解

CourseSniffer 基于 C++17、Qt6 和 libpcap 实现，支持实时网络嗅探和分层协议分析。

当前选择默认路由对应的物理网络接口，通过 libpcap 请求混杂模式，API 激活成功。

本次捕获范围限定为本机与默认网关之间的 ICMP 通信，共捕获三个请求和三个应答。

展开 Ethernet 和 ICMP 字段，可以查看以太网地址、报文类型及序号。

混杂模式的实际捕获范围受网络拓扑和驱动限制，本次记录仅能验证指定两个端点之间的通信捕获。

## 三、回环抓包与分层协议解析

### 操作

1. 在 lo0 接口使用普通模式开始抓包。
2. 自动产生 IPv4、IPv6 的 HTTP 请求与响应、UDP 回声通信，以及 ICMP、ICMPv6 诊断流量。
3. 展示实时更新的数据包列表和状态栏统计信息。
4. 停止抓包，定位 TCP SYN 报文。
5. 展开协议字段树，查看 IP 地址、TCP 端口、序号和标志位，同时展示十六进制原始字节。

### 字幕讲解

切换至回环接口，使用普通模式捕获本机产生的真实网络通信。

数据包列表实时显示 IPv4、IPv6、HTTP、TCP、UDP、ICMP 和 ICMPv6 报文。

停止抓包后，选中 TCP SYN 报文，查看各层协议字段及原始字节。

程序根据链路封装逐层解析数据包，状态栏显示捕获数量和当前可见数量。

## 四、协议逻辑过滤

### 操作

按照以下顺序输入并应用过滤表达式，观察数据包列表变化。

| 过滤表达式 | 字幕讲解 |
| --- | --- |
| `ip.addr == 127.0.0.1 and tcp` | 筛选包含指定 IPv4 地址的 TCP 报文。 |
| `http and tcp.port == 8080` | 筛选使用 8080 端口的 HTTP 报文。 |
| `ipv6 and (tcp or udp)` | 使用括号组合条件，筛选 IPv6 上的 TCP 和 UDP 报文。 |
| `udp.srcport == 9999 and not ipv6` | 根据 UDP 源端口筛选报文，并排除 IPv6 通信。 |
| `icmp` | 单独查看 ICMP 报文。 |
| `icmp6 and ip.dst == ::1` | 筛选目标地址为 IPv6 回环地址的 ICMPv6 报文。 |
| `tcp and (` | 输入非法表达式，检查语法错误提示及上一次有效过滤结果。 |

### 字幕讲解

显示过滤器支持协议名称、IP 地址、源端口、目标端口，以及与、或、非运算和括号。

输入非法表达式时，程序提示语法错误，并保留最近一次有效过滤结果。

显示过滤仅影响数据包列表，录制期间的实际捕获范围由 libpcap 抓包过滤器限定。

## 五、TCP 双向流追踪

### 操作

1. 应用以下过滤表达式。
   `http and (tcp.srcport == 8080 or tcp.dstport == 8080)`
2. 选中 HTTP 数据包，打开 TCP 流追踪窗口。
3. 查看连接双方的 IP 地址、端口及数据量。
4. 展示同一连接中的 HTTP GET 请求。
5. 展示对应的 HTTP 200 响应。
6. 切换至十六进制视图，查看整理后的原始负载。

### 字幕讲解

TCP 流追踪根据连接双方的 IP 地址和端口关联数据包，按照 TCP 序号重组两个方向的数据。

这里可以查看同一条 TCP 连接中的 HTTP GET 请求和 200 响应。

切换至十六进制视图，可以检查重组后的原始字节。

乱序、重传及数据缺口的处理逻辑由核心单元测试覆盖。

## 六、DNS 与 ARP 协议分析

### 操作

1. 关闭 TCP 流追踪窗口，清空捕获记录。
2. 导入固定的离线 PCAP 文件，保留界面中的离线样例标识。
3. 应用 dns 过滤条件，依次查看 DNS 查询、A 记录响应和 AAAA 记录响应。
4. 应用 arp 过滤条件，依次查看 ARP 请求和响应。
5. 展开相应协议字段，展示解析结果。
6. 清空记录，结束演示。

### 字幕讲解

导入固定的离线 PCAP 样例，展示 DNS 和 ARP 协议解析功能。

DNS 解析可以展示事务 ID、查询名称、查询类型及响应记录。A 记录提供 IPv4 地址，AAAA 记录提供 IPv6 地址。

ARP 解析可以展示操作码、发送方和目标方的 MAC 地址及 IPv4 地址。

至此完成实时抓包、分层协议解析、逻辑过滤和 TCP 双向流追踪的功能演示。
